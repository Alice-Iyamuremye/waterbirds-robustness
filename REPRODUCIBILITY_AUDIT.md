# Implementation and Reproducibility Audit

**Scope:** Uploaded Kaggle source archive (`erm_source.zip`), uploaded notebook (`project15ml-4.ipynb`), saved notebook outputs, and the reviewed source now committed under `erm/`.

## 1. Historical run evidence

The uploaded notebook records a single Waterbirds run using ImageNet-pretrained ResNet-18, 50 epochs, ERM and Group DRO, with checkpoint selection by validation worst-group accuracy. Its saved test output reports:

| Method | Macro-average subgroup accuracy (not sample-weighted) | Worst-group accuracy |
|---|---:|---:|
| ERM | 83.07% | 62.62% |
| Group DRO | 86.36% | 74.77% |

Per-group outputs are ERM: 98.63%, 75.88%, 62.62%, 95.17%; Group DRO: 94.28%, 85.41%, 74.77%, 90.97% (group order: landbird-on-land, landbird-on-water, waterbird-on-land, waterbird-on-water). The four test group counts in the notebook are 2,255 / 2,255 / 642 / 642. The reported 83.07% and 86.36% values are arithmetic means of the four subgroup accuracies, not conventional sample-weighted accuracy. They are preserved as historical notebook results and relabelled accordingly.

## 2. Source-code issues found in the uploaded archive

1. **Group DRO absent-group handling:** the original `GroupDROLoss` assigned zero group loss to groups absent from a minibatch, then updated all dual weights. This can decrease the relative weights of groups simply because they were not sampled in that minibatch.
2. **Metric naming:** the original evaluator calculated `np.mean(per_group_accuracy)` and stored it as `overall_accuracy`. This is macro-average subgroup accuracy, not sample-weighted accuracy.
3. **Path-type mismatch:** `run_erm.py` passed a string checkpoint path to functions that used `.stem`, which requires a `Path` object.
4. **Architecture documentation:** `saliency.py` described ResNet-50, while `model.py` configures ResNet-18.
5. **Checkpoint provenance:** the original checkpoints did not retain optimizer/scheduler state or the Group DRO dual weights, limiting exact resumption and inspection.

## 3. Changes made on this review branch

- Added the supplied `erm/` source package to the repository so it no longer depends on an undocumented external Kaggle attachment.
- Reworked Group DRO updates so only groups present in a minibatch update their dual weights. The model objective renormalizes the active weights across groups present in that batch; absent groups are not treated as zero-loss observations.
- Added shape/range checks for group IDs and stable normalization safeguards.
- Checkpoints now include optimizer/scheduler states, seed, Group DRO weights, and validation metadata.
- Evaluation now reports both sample-weighted accuracy and macro-average subgroup accuracy, plus per-group counts. `overall_accuracy` now means sample-weighted accuracy.
- Normalized checkpoint arguments to `Path` in evaluation, driver, and saliency paths.
- Corrected the ResNet-50 wording to ResNet-18 and retained Grad-CAM as qualitative evidence only.
- ERM checkpoints now also preserve optimizer/scheduler state and seed metadata.

## 4. Important distinction: historical results vs reviewed implementation

The saved notebook outputs were generated by the historical source code supplied in the ZIP. The reviewed Group DRO implementation changes minibatch dual-weight handling and therefore is **not byte-for-byte or algorithmically identical** to the historical run. The historical metrics must not be presented as results from the corrected code. A fresh run is required to obtain corrected implementation results.

The corrected evaluator can compute sample-weighted accuracy on a new run. The rounded subgroup percentages in the notebook are insufficient to reconstruct exact sample-weighted accuracy reliably, so no retroactive sample-weighted figure is claimed here.

## 6. Current conclusion

The historical notebook documents one run in which Group DRO has higher worst-group accuracy than ERM on Waterbirds. The source review identified and corrected important implementation/reporting risks, but the revised implementation has **not yet been rerun on the dataset**. Therefore, the historical performance numbers remain historical evidence only; they do not validate the corrected code. Grad-CAM visualizations are qualitative and do not prove causal background reliance.
